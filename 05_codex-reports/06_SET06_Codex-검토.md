# [C-SET-06] 스캔 계획 구현 가능성 검토

**blocking 5 · should-fix 5 · nit 0.** 대상 Notion 화면설계서를 새로 읽고 교차 대조함. 현재 명세만으로 경로·자동 산출·준비 판정의 핵심 로직에 착수하기 어려움. 아래는 발견과 확인 질문이며, 값의 우열이나 기획 방향은 판정하지 않음. 기존 미결(인수인계서 §10, Notion `🛠️ 개발팀 논의 필요/수정 사항`)과 문서가 인정한 오버랩 역산의 반복 수렴 문제는 제외함.

## blocking

1. **검사면 치수의 출처가 연결되지 않음.** ① `[C-SET-06]`은 검사 전체에 계획 하나를 적용하면서 오버랩 비율은 ‘선택한 배치면 면적’, 이동 높이 비율은 ‘배치면 height’를 분모로 사용함. ② `[C-SET-06]` §레이아웃·§오버랩 간격·§탐촉자 이동 조건, `[C-SET-05] 배치` §맵핑 대상, `[C-SET-03] 모재` §사양. ③ 배치면은 홀더마다 선택되고 여러 면이 가능하지만 스캔 계획에는 면 선택이 없음. 박스형 모재도 외경·높이만 등록하므로 각 면의 가로·세로·면적을 확정할 수 없음. 타일 수·비율·잘린 구역 비율이 같은 입력에서 달라질 수 있음. ④ **확인 질문:** 검사면을 어떤 홀더·면으로 확정하며, 형상별 면의 치수는 어디서 얻는가? 세 문서의 참조 관계에 명시 필요.

2. **자동 산출 규칙이 비어 있음.** ① 전체·섹션·타일 예상 시간, 타일·섹션 수, 잘린 구역 비율을 자동 표시하나 산출 기반만 나열함. ② `[C-SET-06]` §스캔 경로 미리보기·§참고, `[C-PRJ-02] 대시보드` §정보 카드. ③ 경계에서 타일을 자르는 방식, 오버랩 반영, ‘섹션=타일 N개’의 N·묶음 규칙, 타일 이동·교정 시간을 포함하는 시간식이 없음. 잘린 구역도 어느 방향의 잔여 구역을 합산할지 정해지지 않음. ④ **확인 질문:** 타일 배치·잔여 면적·섹션 그룹·3단계 시간의 산식과 반올림 단위를 무엇으로 확정하는가? `[C-SET-06]` 자동 산출 절에 필요.

3. **속도 안전 상한을 계산할 값과 적용 범위가 없음.** ① `min(로봇 최대 속도, (PRF÷Average)×수집 간격, 규격 상한)`을 약속함. ② `[C-SET-06]` §탐촉자 이동 조건·§참고, `[C-SET-02] DAQ-장비 정보` §DAQ 장비 정보, `[C-SET-02] DAQ-I/O 장비 설정` §기본 입력, `03_dev_handoff/PRF_Auto_Calculation_Spec_v1.0.md:12,337-340`. ③ `Average`의 값·출처와 `규격 상한`의 수치·단위가 없고, 로봇 상한과 DAQ별 최대 속도의 관계도 없음. DAQ가 여러 대면 비율의 기준값도 미정임. I/O 수집 간격의 기본값 `0.00 mm`는 명시된 `속도÷수집 간격`에서 0으로 나누게 됨. PRF 자동 계산 사양은 고정형 단일 채널 범위라 스캔형 PRF 값의 출처를 대신하지 못함. ④ **확인 질문:** 각 상한·Average·스캔형 PRF의 출처, 다중 DAQ 합성 기준, 수집 간격의 유효 범위를 어디에 정의하는가?

4. **▶ 선행조건 두 개의 충족 판정이 불가능함.** ① 스캔형은 엔코더 캘리브레이션과 검사 시작 트리거 설정을 요구함. ② `[C-SET-06]` §선행조건, `[C-SET-02] DAQ-I/O 장비 설정` §엔코더 값·§디지털 I/O·§저장. ③ I/O 문서에는 엔코더 분해능·리셋·주기적 캘리브레이션 언급만 있고 실행·성공·만료 상태가 없음. 디지털 I/O는 8개 핀의 현재값 `GPI`만 제시하며 ‘검사 시작’에 해당하는 선택값·저장 판정이 없음. 따라서 두 불리언 조건을 산출할 수 없음. ④ **확인 질문:** 캘리브레이션의 완료 기록과 유효 기간, 시작 트리거의 핀/이벤트 매핑 및 저장 판정은 무엇인가? I/O 문서와 선행조건 절에 연결 필요.

5. **장비 미연결 시 ▶ 동작이 두 문서에서 다름.** ① `[C-SET-06]`은 DAQ 미연결이면 ▶ 비활성·F6 무반응, `[C-PRJ-03]`은 미연결 상태에서 ▶ 클릭 시 연결 필요 팝업을 띄움. ② `[C-SET-06]` §선행조건, `[C-PRJ-03] 종합 결과` §▶/■ 측정 준비 완료. ③ 동일 상태에서 버튼이 클릭 가능한지부터 달라 팝업에 도달할 수 있는지 정할 수 없음. ④ **확인 질문:** 미연결 시 ▶은 클릭 가능한 차단 버튼인가, 비활성 버튼인가? 두 문서의 상태·F6·팝업 조건을 일치시킬 필요.

## should-fix

6. **속도 상한별 처리 경계가 불명확함.** ① 직접 입력 속도가 DAQ 최대 속도를 넘으면 장비 정보 문서는 `error`, 스캔 계획은 로봇·PRF·규격 상한 초과 시 `데이터 누락 발생` 경고로 적음. ② `[C-SET-02] DAQ-장비 정보` §DAQ 장비 정보, `[C-SET-06]` §탐촉자 이동 조건. ③ DAQ 상한과 로봇 상한이 같은지, 서로 다른 한계라면 어느 조건부터 `error`·경고로 표시하는지 구별되지 않음. ④ **확인 질문:** DAQ 최대 속도 초과와 스캔 계획 산출 상한 초과를 각각 `error`·경고·저장 차단 중 어떻게 처리하는가?

7. **양방향 환산값의 저장 기준과 재계산 조건이 없음.** ① 이동 높이 mm↔%, 속도 mm/s↔%는 각 분모가 정해지면 단순 환산 가능하여 오버랩 역산의 반복 수렴 문제는 없음. ② `[C-SET-06]` §오버랩 간격·§탐촉자 이동 조건·§저장, `[C-SET-02] DAQ-장비 정보` §최대 속도. ③ 사용자가 입력한 쪽과 계산된 쪽 중 무엇을 원본으로 저장하는지, 모재 배치면·DAQ 최대 속도 변경 시 무엇을 고정하고 무엇을 재계산하는지 미정임. ④ **확인 질문:** 세 쌍별 원본 필드·저장값·분모 변경 시 재계산/재확인 규칙은 무엇인가? `[C-SET-06]` 저장 절에 필요.

8. **고정형 혼재와 자동 연동 OFF의 적용 범위가 비어 있음.** ① 교정 주기만 스캔형/고정형을 분기하고, 자동 연동 OFF는 ‘다음 타일 자동 진행’ 토글만 비활성화한다고 명시함. ② `[C-SET-06]` §자동화 토글·§기본·§선행조건, `[C-SET-02] DAQ-장비 정보` §솔루션 유형, `[C-PRJ-03]` §▶/■. ③ 전 DAQ 일괄 준비인 프로젝트에서 고정형이 섞이거나 모두 고정형일 때 타일·속도·엔코더·자동 주행 조건이 어느 장비에 적용되는지, 연동 OFF에서 계획·미리보기·저장이 계속 필요한지 알 수 없음. ④ **확인 질문:** 혼재/전부 고정형과 연동 OFF 각각에서 필드·산출·선행조건·저장의 적용 대상을 어떻게 나누는가?

9. **경고의 입력 조건과 커버폭 값이 덜 정의됨.** ① 오버랩 `0` 경고는 명확하지만, 유효 커버폭 초과 경고에는 커버폭의 수치 출처가 없고 ‘잘린 비율이 클수록 재조정’에는 경고 임계값이 없음. ② `[C-SET-06]` §오버랩 간격·§탐촉자 이동 조건·§스캔 경로 미리보기, `[C-SET-02] DAQ-홀더 설정` §중앙 3D 영역·§사양. ③ 홀더 치수와 기준 탐촉자의 검사 폭 언급만으로 실제 유효 커버폭을 계산할 수 없음. ‘잘린 비율’은 경고인지 안내인지도 불명확함. ④ **확인 질문:** 커버폭의 저장/산출 출처와 초과 판정식은 무엇인가? 잘린 비율은 수치 임계 경고인지 안내 문구인지?

10. **저장 예외와 기존 계획의 효력 범위가 없음.** ① `[C-SET-06]`은 저장 성공만 정의함. ② `[C-SET-06]` §저장·§스캔 경로 미리보기, `[C-SET-03] 모재` §저장 조건, `[C-PRJ-03]` §설정 변경 시 검사 마감·§새검사. ③ 진행중 검사에서 설정 저장의 확인/취소·새검사 생성은 `[C-PRJ-03]`에 정의돼 있음. 반면 저장 실패·저장 전 이탈, 같은 계획 재저장, 저장 후 모재 치수 변경 시 기존 계획의 유효성·자동 산출·완료 검사 데이터 영향은 정해지지 않음. ④ **확인 질문:** 실패/이탈 시 미저장값 처리, 재저장의 버전·덮어쓰기, 참조 모재 변경 시 계획 재확인과 기존 검사 보존 규칙은 무엇인가? `[C-SET-06]` 저장 절에서 `[C-PRJ-03]` 진행중 검사 절도 참조 필요.

**교차 대조에서 일치한 항목:** 교정 만료 시 현재 타일 후 다음 타일 차단(`[C-SET-06]` §자동화 토글, `[C-PRJ-05] 교정-사이드바` §교정 주기), 타일 간 겹침과 채널 간 오버레이의 구분(`[C-SET-06]` §자동화 토글, `[C-PRJ-06] 결과 분석` §표시 옵션·§좌측 스캔 영역), 대시보드의 네 산출값 표시(`[C-PRJ-02]` §정보 카드). 새 개발 확인 항목으로 옮길 후보는 3·4·9의 장비/SDK 값과 판정 정보이며, Codex는 Notion에 직접 반영하지 않음.
