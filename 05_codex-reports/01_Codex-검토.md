# DGS 감도 보정 재검토

**blocking 3 · should-fix 6 · nit 0.** 세 역할 문서와 대상 Notion 문서를 다시 읽었습니다. **화면 동작의 상당 부분은 정의돼 있지만, DGS 채널의 사후 저장·재분석은 현재 명세만으로 확정해 구현하기 어렵습니다.** 아래는 어긋난 사실과 빈 조건의 보고이며, 어느 값을 채택할지는 판정하지 않았습니다. 출처는 `[C-PRJ-05] 교정-사이드바`, `[C-PRJ-05] 교정-파형 영역`, `[C-PRJ-06] 결과 분석`입니다.

## Blocking

1. **DGS 채널의 사후 Digital Gain 변경 허용 범위가 다릅니다.** 결과 분석 §채널별 조정·§사후 변경 허용 범위는 수정을 허용하지만, `03_dev_handoff/Result_Analysis_Storage_Spec_v1.0.md:92`는 DGS `current` 변경을 `DGS Curve`·`Offset`으로 한정합니다. 저장 검증 규칙이 갈립니다. **확인 질문:** Digital Gain을 DGS `current`에 저장하는가? Claude 반영 위치는 저장 사양 §5-5와 결과 분석의 해당 두 섹션입니다.
2. **DGS 변경값의 저장 구조가 빠져 있습니다.** 결과 분석 §채널별 조정은 `DGS Curve`·`Offset 1~4` 수정과 저장을 명시하지만, 저장 사양 `:47-67`의 채널별 세트에는 두 필드가 없습니다. 초기값으로 되돌리거나 재열기할 때 어떤 값을 읽을지 정할 수 없습니다. **확인 질문:** 두 값과 Offset 행의 개수·값을 `origin/current`에 어떤 필드로 담는가? 저장 사양 §3에 명시가 필요합니다.
3. **DGS raw 진폭의 복원식 적용 범위가 불명확합니다 — 확인 필요.** 사이드바 §④는 실제 검사 총 Gain을 `글로벌 Gain + Transfer Corr.`로 설명하지만, 저장 사양 `:27-36`의 저장·복원식은 `Digital Gain + TCG(t)`만 사용합니다. **확인 질문:** DGS 채널에서 TCG 항은 어떻게 처리하며, Transfer Corr.는 raw 저장 전에 적용되는가, 표시·평가 때만 적용되는가? 답에 따라 저장 사양 §2-1의 DGS 분기가 필요합니다.

## Should-fix

4. **`[✨]` 성공 상태의 유효 범위가 비어 있습니다.** 사이드바 §④는 성공 후 `[↑ Record]`를 활성화합니다. 파형 영역 §Gain·§Gate에서는 그 사이 선택 게이트와 게이트 위치·폭·임계값을 바꿀 수 있습니다. **확인 질문:** 어떤 변경에서 성공 상태를 해제하며, 80% 도달의 허용 오차는 얼마인가? 두 화면의 버튼 조건에 반영할 사항입니다.
5. **방식 왕복 시 기록 상태가 모호합니다.** 사이드바 §④는 TCG↔DGS 전환 후 각 방식의 입력값을 보존하고, DGS 중에는 수동 Gain 입력을 막습니다. 그러나 TCG에서 Gain을 바꾼 뒤 DGS로 돌아왔을 때 기존 기준 에코 기록·Record 활성 상태를 어떻게 처리할지는 없습니다. **확인 질문:** 이 경로에서 기록을 유지·무효화·재확인 중 어떻게 다루는가? 사이드바 §④의 전환 및 재기록 조건에 명시할 사항입니다.
6. **DGS 설정 가능 시점의 서술이 다릅니다.** 사이드바 §④는 영점·음속 *완료 후에만 설정*이라고 하고, 같은 문서 §섹션 간 의존 관계는 순서를 강제하지 않으며 선행 미완료 시 경고와 유효 판정 보류를 규정합니다. **확인 질문:** 선행 단계 미완료 때 DGS 입력 자체를 막는가, 입력은 허용하고 완료만 보류하는가? 두 섹션의 동작을 맞춰야 합니다.
7. **`Ampl Correct`의 조건 분기가 없습니다.** 사이드바 §④는 보정이 필요한 기준 반사체에서만 활성이라고 하나 `FBH·SDH·BW`별 활성 여부를 적지 않습니다. **확인 질문:** 각 선택값에서 활성·비활성 및 기존 입력값 처리 방식은 무엇인가? 사이드바 §④에 조건표가 필요합니다.
8. **DGS 수치 입력 검증값이 없습니다.** 사이드바 §④에는 단위·기본값·Offset 최대 4행이 있지만, `DGS Curve`·`Ref Size`·감쇠값·보정값의 허용 범위와 소수 정밀도는 없습니다. **확인 질문:** 각 필드에서 0·음수·범위 초과·자릿수 초과를 어떻게 처리하는가? 사이드바 §④ 입력 규칙에 명시할 사항입니다.
9. **`Transfer Corr.` 단위 표기가 다릅니다 — 도메인 교차검증.** 사이드바 §④는 `dB`, `01_materials/DGS_AVG_수집자료_정리본.md` §2 `MAT ATTN`은 `dB/m`로 표기합니다. **확인 질문:** 어느 단위를 사용할 것인가? 이는 기존 개발 확인 9건에 있는 *Offset* 단위 질문과는 다른 필드입니다.

## 정의된 부분과 작성 규칙

TCG/DGS 혼재 시 일괄 TCG의 적용 대상, 종파의 경사각 단계 제외, `BW`의 `Ref Size=null`은 명시돼 있습니다(결과 분석 §일괄 감도 교정, 사이드바 §④·§섹션 간 의존 관계). `[✨]` 실패 2종, 화면 이탈 시 교정 세션 보존, Record 재실행 시 덮어쓰기, raw·`origin` 불변도 확인했습니다(파형 영역 §Gain, 사이드바 §탐촉자 선택·§④, 저장 사양 §5). 기존 데이터에 대한 **DGS 사후 변경 결과**는 blocking 1~3이 정리돼야 확정됩니다. 지정한 화면 문서의 DGS 관련 본문에서 `vN.N`, 폐기 기획 이력, `확인 필요` 섹션 위반은 발견하지 못했습니다(`AGENTS.md` §용어).

Notion `🛠️ 개발팀 논의 필요/수정 사항`의 기존 DGS 9건과 대조한 **추가 후보는 2건**입니다: ① DGS 채널의 raw 저장 전 증폭 요소와 Transfer Corr. 적용 단계(blocking 3), ② `[✨]` 80% 성공 판정 허용 오차·장비 Gain 해상도(should-fix 4). 나머지는 사용자·Claude가 명세 조건과 문서 값을 정리할 질문입니다.
