# 의심 지점 마킹 반영 후 재검토

> Codex · 2026-11-06 · 대상: `28_MARK_Claude-반영.md` §3의 4개 항목. Notion `[C-PRJ-06] 결과 분석`·`[C-RPT-02] 스캔 보고서`·`[C-PRJ-03] 종합 결과`를 새로 읽고 대조함. §4와 기존 미결은 제외. 아래는 발견과 질문이며 기획 판정이 아님.

**blocking 1 · should-fix 3 · nit 0**

## 발견

### B1 · blocking · 로봇 마킹 후 결과 저장 실패의 상태가 정의되지 않음

1. **무엇이:** 각 행의 `진행중` 저장 성공 후 로봇에 전송하는 규칙은 반영됨. 그러나 로봇이 실제로 마킹한 뒤 `완료` 상태·실행 일시의 저장이 실패할 때, 재시작 복구는 남은 `진행중`을 일괄 `실패(실행 중단)`로 바꿈. 그 행을 다시 실행하면 실제 표시를 중복할 수 있음. 완료 건 재실행이 실패한 경우 이전 `실행 일시`의 보존 여부도 없음.
2. **어디서:** Notion `[C-PRJ-06] 결과 분석` §우측 사이드바 — 마킹 탭 ‘마킹 실행’·‘저장’; `03_dev_handoff/Result_Analysis_Storage_Spec_v1.0.md:109-120,135`.
3. **왜 문제인가:** 물리적 표시 여부와 검사 기록의 상태가 달라질 수 있어 재시도 대상을 안전하게 결정할 수 없음. 통신·회신 경로 자체는 기존 개발 확인 항목이므로 여기서 다시 묻지 않음.
4. **확인 질문:** 로봇의 성공 회신 후 `완료` 저장이 실패하면 화면·재시작 복구·재실행 허용을 어떻게 처리하는가? 완료 건 재실행 실패 시 기존 성공 일시는 유지하는가?

### S1 · should-fix · 마킹 번호 카운터의 영속 위치·갱신 경계가 없음

1. **무엇이:** `nextNo`를 검사별로 보관한다는 주석은 있으나 저장 대상 표와 데이터 예시에는 카운터의 소유 레코드가 없음. 마지막 마킹 행 삭제 뒤에도 번호 미재사용을 보장할 저장 절차가 명시되지 않음.
2. **어디서:** Notion `[C-PRJ-06] 결과 분석` §우측 사이드바 — 마킹 탭 ‘마킹 1건 항목’; `03_dev_handoff/Result_Analysis_Storage_Spec_v1.0.md:18-24,97-100,116-123`.
3. **왜 문제인가:** 행 목록의 최대 번호로 다음 번호를 계산하면 마지막 행 삭제·재시작 후 같은 번호가 다시 나올 수 있음. 추가 저장 실패 시 번호 미소비 규칙도 카운터와 행의 갱신 경계에 달림.
4. **확인 질문:** 검사별 `nextNo`는 어디에 영속 저장하며, 행 추가와 카운터 증가는 어떤 단위로 함께 확정하는가?

### S2 · should-fix · 마킹 탭에서 후보를 다시 고를 때 채널 확인 경로가 불명확함

1. **무엇이:** 첫 마킹 추가 후 사이드바는 `마킹` 탭으로 전환됨. 다음 자동 후보를 클릭하면 검출 채널이 ‘사이드바에서 펼쳐짐’으로 적혔지만, 채널 아코디언은 `교정` 탭에만 있음. `[마킹 추가]` 전 채널 변경 가능 규칙을 이 상태에서 어떻게 수행하는지 없음.
2. **어디서:** `28_MARK_Claude-반영.md:17`; Notion `[C-PRJ-06] 결과 분석` §우측 사이드바 — 헤더·§우측 사이드바 — 채널별 조정·§우측 사이드바 — 마킹 탭 ‘마킹 추가’.
3. **왜 문제인가:** 후보 클릭으로 A-scan·B/D-scan 대상 채널도 바뀌지만(`§우측 상단 A-scan`), `마킹` 탭에서는 선택된 채널과 변경 수단이 보이지 않음.
4. **확인 질문:** `마킹` 탭이 열린 상태에서 후보 클릭 시 `교정` 탭으로 전환하는가? 그렇지 않다면 사용자가 추가 전 채널을 어디서 확인·변경하는가?

### S3 · should-fix · 데이터는 있지만 선택 게이트에 피크가 없는 영역의 추가 조건이 없음

1. **무엇이:** 데이터가 전혀 없는 영역은 추가 불가로 정의됨. 반면 데이터가 있어도 선택 게이트가 피크를 포착하지 못한 영역에서는 필수 `깊이`·`에코 높이`를 채울 수 없는데 처리 규칙이 없음.
2. **어디서:** Notion `[C-PRJ-06] 결과 분석` §우측 사이드바 — 마킹 탭 ‘마킹 추가’·‘마킹 1건 항목’; `03_dev_handoff/Result_Analysis_Storage_Spec_v1.0.md:100-106`.
3. **왜 문제인가:** ‘채널 데이터 있음’만으로 추가 가능 여부를 판단하면 값이 비어 있는 마킹을 만들 수 있음.
4. **확인 질문:** 선택 게이트에서 피크가 0건이면 추가를 막는가? 막는다면 어떤 안내를 표시하는가?
