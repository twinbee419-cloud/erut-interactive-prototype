## 2. Codex 검토 요청

> 1~2는 반영 항목 일반 점검 · **3~7은 Claude가 반영하며 확신하지 못한 지점** — 구체적으로 대조해 주세요.

1. **S1~S4 반영 문구** — 일괄 교정 · 사이드바 두 문서 사이에서 서로 어긋나지 않는지.
2. **결과 팝업 사유 3종**(미충족 항목명 / 측정·동작 실패 / 재측정 필요)과 `[확인]` 이동 규칙 3종이 1:1로 대응하는지 · 한 채널에 사유가 여러 개일 때 표시·이동 우선순위가 정의돼 있는지.
3. **`재수행 필요 ({원인} 변경)`의 원인이 언제 사라지는가** — 예: Pulser 변경으로 ①·②·④가 재수행 필요가 된 뒤 ①만 다시 하면 ②·④의 원인 표시는 그대로 `Pulser Control 변경`인지, ① 재수행으로 원인이 `영점 변경`으로 바뀌거나 추가되는지(① 변경 → ②·③·④ 무효 규칙과 겹침). 사이드바 §섹션 간 의존 관계만으로 구현 가능한지.
4. **원인 라벨 표기** — 원인 = "바뀐 선행 항목명"이라고 했는데, ① 영점 안에서 바뀐 값은 `Delay` · `Wedge Delay`이고 섹션명은 `영점`임. 원인 라벨이 섹션명(`영점`)인지 필드명(`Wedge Delay`)인지 명세에서 하나로 정해지는지.
5. **일괄 교정 모달 안의 Echo 측정 실패 표시** — 사이드바 ②에는 행 인라인 에러를 정의했지만, **일괄 교정 모달 안**에서는 "✓ 미표시 · 미측정으로 남음"뿐임. 모달 안에서 실패한 채널을 pane 단위로 식별할 표시가 필요한지(8채널 중 어느 채널이 실패했는지 알 수 있는지), 결과 팝업까지 가야만 알 수 있는 구조인지.
6. **집계 범위 '배치된 홀더 전체' + 페이지 이동 시 입력값** — `[완료]`가 모든 페이지를 판정하려면 페이지를 넘길 때 각 홀더의 미저장 입력값이 모달 안에서 유지돼야 함. `[C-PRJ-05-02]` §대상 선택 '페이지네이션 = 홀더 단위 전환 · 사이드바 값 교체'가 이 유지를 보장하는 서술인지 · 한 번도 열지 않은 홀더 페이지는 기존 저장값으로 판정되는지.
7. **사유 표기와 완료 조건 항목명 일치** — 결과 팝업 사유의 `{단계}`(예 `감도`)와 완료 조건 문구의 항목명(`감도 보정 유효`)·사이드바 섹션명(`④ 감도 보정`)이 같은 이름으로 읽히는지.
