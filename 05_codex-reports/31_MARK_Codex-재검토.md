# 의심 지점 마킹 상태·모드 반영 재검토

> Codex · 2026-11-06 · 대상: `30_MARK_Claude-반영.md` §3의 3개 항목. Notion `[C-PRJ-06] 결과 분석`을 새로 읽고 `03_dev_handoff/Result_Analysis_Storage_Spec_v1.0.md` §3-1과 대조함. §4와 기존 미결 제외. 기획 판정 없이 어긋남·공백만 보고.

## 발견

### B1 · blocking · `결과 미확인` 행을 삭제할 수 있음

1. **무엇이:** 재시작 때 `진행중`을 `실패(결과 미확인)`으로 바꾸고, 재실행 전에는 모재 확인 팝업을 띄움. 그런데 `실패` 행은 삭제 가능해, 실제로 로봇이 표시했을 수도 있는 기록을 확인 없이 제거할 수 있음.
2. **어디서:** Notion `[C-PRJ-06] 결과 분석` §우측 사이드바 — 마킹 탭 ‘목록 테이블’·‘마킹 실행’; `Result_Analysis_Storage_Spec_v1.0.md:122-124`.
3. **왜 문제인가:** 실제 표시가 남은 `완료` 건은 기록 보존을 위해 삭제 금지인데, 표시 여부가 불명인 건에는 같은 보호가 적용되지 않음.
4. **확인 질문:** `결과 미확인` 사유의 `실패` 행도 삭제 가능한가? 가능하다면 물리 표시 여부를 확인하지 않은 기록 삭제를 어떻게 다루는가?

### B2 · blocking · `완료` 건 재실행 중 종료 시 이전 성공 기록의 상태가 불명확함

1. **무엇이:** 실행 전 모든 행에 `running` 저장을 요구하고, 재시작 때 `running`을 일괄 `failed(결과 미확인)`으로 복구함. 반면 `완료` 건의 재실행이 실패하면 기존 `완료`·실행 일시를 유지함. 재실행 도중 프로그램이 종료된 경우 어느 규칙이 적용되는지 없음.
2. **어디서:** Notion `[C-PRJ-06] 결과 분석` §우측 사이드바 — 마킹 탭 ‘마킹 실행’; `Result_Analysis_Storage_Spec_v1.0.md:109-123`.
3. **왜 문제인가:** 이미 물리 표시와 성공 기록이 있는 행이 재시작 후 `실패`로 바뀌거나 이전 실행 일시를 잃을 수 있음.
4. **확인 질문:** `완료` 건 재실행의 진행 상태는 기존 성공 기록과 별도로 보관하는가? 그 도중 종료되면 상태·기존 실행 일시·`결과 미확인` 사유를 어떻게 표시하는가?

### S1 · should-fix · 로봇 실패 결과의 저장 실패 처리가 없음

1. **무엇이:** 로봇 성공 후 `완료` 저장 실패는 경고·자동 재저장으로 정의됨. 로봇이 실패했다고 회신했는데 `실패` 상태 저장도 실패하면 화면 상태, 다음 행 실행, 재시작 복구 기준이 없음.
2. **어디서:** Notion `[C-PRJ-06] 결과 분석` §우측 사이드바 — 마킹 탭 ‘마킹 실행’; `Result_Analysis_Storage_Spec_v1.0.md:120-123`.
3. **왜 문제인가:** DB에는 `진행중`이 남아도 화면에는 실패가 확인된 상태여서, 재시작 시 실제 결과를 `결과 미확인`으로 바꿀 수 있음.
4. **확인 질문:** 실패 회신 후 상태 저장이 실패하면 경고·재저장·후속 행 진행을 어떻게 처리하는가?

### S2 · should-fix · C-scan 드래그·클릭의 마킹 모드 우선순위가 없음

1. **무엇이:** C-scan 드래그는 평소 팬이고, 마킹 모드에서는 사각형 지정임. 결함 구역 클릭도 평소 확대·A-scan 표시와 마킹 모드의 확인 팝오버가 겹침. 모드 ON에서 기존 동작을 함께 수행하는지, 마킹 동작이 대신하는지 적혀 있지 않음.
2. **어디서:** Notion `[C-PRJ-06] 결과 분석` §좌측 스캔 영역 (C-scan)·§우측 사이드바 — 마킹 탭 ‘마킹 추가’.
3. **왜 문제인가:** 동일한 입력으로 팬·확대·커서 변경·마킹 영역 지정이 동시에 발생할 수 있어 구현별 반응이 갈림.
4. **확인 질문:** 마킹 모드 ON일 때 빈 영역 드래그와 후보 사각형 클릭은 기존 팬·확대·십자 커서 동작 중 무엇을 실행하는가? 모드 중 화면 이동은 어떻게 하는가?

### S3 · should-fix · 마킹 모드에서 다른 모드·탭으로 이동하는 규칙이 한 방향뿐임

1. **무엇이:** 🚩을 켜면 측정·영역 선택 모드가 해제되고 `마킹` 탭이 열림. 그 뒤 측정·영역 선택을 누르거나 사이드바 `교정` 탭으로 바꾸면 🚩 모드와 열린 팝오버를 유지·취소하는지 정의되지 않음.
2. **어디서:** Notion `[C-PRJ-06] 결과 분석` §좌측 스캔 영역 (C-scan)·§우측 사이드바 — 헤더·§우측 사이드바 — 마킹 탭 ‘마킹 추가’.
3. **왜 문제인가:** 도구 모드가 중첩되거나, 확인 전 사각형이 남은 채 다른 작업으로 넘어갈 수 있음.
4. **확인 질문:** 다른 측정 도구 선택·`교정` 탭 전환·Esc 각각에서 마킹 모드와 미확정 팝오버는 어떻게 처리하는가?

### S4 · should-fix · 팝오버 취소 시 채널 변경의 복귀 여부가 없음

1. **무엇이:** 팝오버 드롭다운 변경은 사이드바 펼친 채널과 A-scan·B/D-scan 대상을 즉시 바꿈. `[취소]`는 지정한 영역을 버린다고만 적혀 있어, 채널 선택도 이전 값으로 되돌리는지 불명확함.
2. **어디서:** Notion `[C-PRJ-06] 결과 분석` §우측 사이드바 — 마킹 탭 ‘확인 팝오버’; §우측 상단 A-scan; §우측 사이드바 — 채널별 조정.
3. **왜 문제인가:** 마킹을 저장하지 않아도 다른 차트의 대상 채널이 바뀐 채 남을 수 있으며, 취소 후 상태를 구현자가 임의로 정하게 됨.
4. **확인 질문:** `[취소]`·Esc·팝오버 밖 클릭 시 펼친 채널과 A-scan·B/D-scan 대상을 유지하는가, 팝오버 전으로 복구하는가?

### N1 · nit · 번호 카운터 갱신이 저장 트리거 표에 빠짐

1. **무엇이:** §3-1은 마킹 추가 시 검사 메타의 `nextMarkingNo`를 행과 함께 갱신하지만, §4는 마킹 추가 트리거의 DB 변경을 `markings[]만`으로 적음.

3. **왜 문제인가:** 같은 사양의 저장 대상 서술이 달라 구현자가 카운터 갱신을 누락할 수 있음.
4. **확인 질문:** §4 마킹 추가 트리거에 검사 메타 `nextMarkingNo` 갱신도 적을 것인가?
