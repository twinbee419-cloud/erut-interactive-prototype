## 1. 진입 · 표시 조건

- 대상 = 불러온 **완료 검사** 1건 · 검사를 불러오기 전에는 `마킹` 탭 빈 상태
- 마킹 지정은 **C-scan 2D에서만** · `3D View` ON이면 지정 불가(측정 도구 3종과 같은 조건) · 목록·실행은 3D에서도 가능
- C-scan 위 **마킹 영역 오버레이** — 사각형 + 번호 라벨(`M-01`) · 상태별 표시 구분 · 헤더 표시 옵션에 `마킹 표시`(체크박스 · 기본 ON) 추가

## 2. 마킹 추가

### 2-1. 경로 2종

| 경로 | 동작 |
|---|---|
| ① 직접 | 영역 선택(▣)으로 사각형을 그림 → 선택된 사각형에 **`[마킹 추가]`** 표시 → 클릭 시 목록에 1건 추가 |
| ② 후보 | `결함 자동 식별` ON일 때 자동으로 그려지는 결함 구역 사각형을 클릭 → 같은 **`[마킹 추가]`** |

- `[마킹 추가]` 위치는 Figma 작업 시 결정 · 동작 기준은 **현재 선택된 사각형 1개**
- 추가 후 사이드바가 `마킹` 탭으로 전환되고 새 행 하이라이트
- 측정선(📏 2점 직선)은 영역이 아니므로 마킹 추가 대상 아님

### 2-2. 마킹 1건의 항목

| 항목 | 값 | 비고 |
|---|---|---|
| 번호 | `M-01`부터 검사 단위 연번 | **삭제해도 번호 재사용 안 함** — 현장 기록지가 번호로 참조하므로 |
| 시작 X·Y / 끝 X·Y | mm · 모재 전체 기준 · 정수 | 사각형의 두 꼭짓점 |
| 채널 | 경로 ① = 사이드바에서 펼친 채널(A-scan 대상) / 경로 ② = 그 구역을 검출한 채널 | |
| 깊이 | mm | 영역 안 **최대 진폭 지점**의 값 |
| 에코 높이 | %FSH | 같은 지점 |
| 메모 | 자유 입력 · 최대 100자 · 선택 | placeholder `관찰 사실만 입력해 주세요.` · 유형·등급 선택지 없음 |
| 상태 | `대기` / `진행중` / `완료` / `실패` | §4 |
| 추가 일시 · 실행 일시 | `YYYY-MM-DD HH:mm` | 실행 일시는 `완료` 시 기록 |

- **깊이·에코 높이는 추가 시점 값으로 동결** — 이후 Gain·Gate를 사후 조정해도 바뀌지 않음(물리 마킹과 기록을 일치시키기 위해)

### 2-3. 실패·예외

| 상황 | 처리 |
|---|---|
| 영역 안에 선택 채널 데이터 없음(스캔 누락 구간) | 추가 불가 · 인라인 `선택한 영역에 이 채널의 데이터가 없습니다.` |
| 기존 마킹과 영역이 겹침 | **추가 허용** · 겹친다는 안내만 표시(겹친 결함을 따로 기록해야 할 수 있음) |

## 3. 마킹 목록 (`마킹` 탭)

- **테이블 컬럼** — `☐` · `번호` · `위치`(시작~끝 X·Y) · `채널` · `깊이` · `에코 높이` · `상태` · `[🗑]`
- 정렬 = 번호 오름차순 고정
- **행 클릭** → C-scan이 해당 영역으로 이동·하이라이트 + 아래 상세(메모 편집·일시)
- **편집** — 메모만 · 위치·채널은 수정 불가(삭제 후 다시 추가)
- **삭제 `[🗑]`** — `대기`·`실패`만 가능 · **`완료` 건은 삭제 불가**(모재에 실제 표시가 남아 있어 기록과 어긋나면 안 됨 · 검사 기록 불변 보관 = 업무_프로세스 §4-4②) · 공통 삭제 모달
- 푸터 **`[마킹 실행]`** — 체크한 행이 1건 이상일 때 활성

## 4. 마킹 실행

### 4-1. 실행 조건 · 실패

| 조건 | 미충족 시 |
|---|---|
| 로봇 연결 | 팝업 `로봇 연결 필요` · 본문 `로봇이 연결되어 있지 않습니다. 연결 상태를 확인해 주세요.` |
| 로봇이 **이 검사의 시작점**을 인식한 상태 | 팝업 `시작점 인식 필요` · 본문 `검사 시작점에서 로봇의 위치를 먼저 맞춰 주세요.` |

- **좌표 근거** — 결과 데이터의 X·Y는 **시작점 기준 절대좌표**(구매시방서 §4.1 "절대좌표(엔코더)")라, 로봇을 다시 붙여도 **같은 시작점에서 출발하면 같은 지점을 찾을 수 있음**. 실행 조건은 그 출발점을 맞췄는지만 확인함
- "이 검사의 시작점"인지 판별하는 방식(시작점 QR의 모재 식별 등)은 개발 확인(§8-2)

### 4-2. 진행

- 체크한 건을 **번호 순서로** 로봇에 전송 · 각 행 `대기` → `진행중` → `완료` / `실패`
- `실패` — 행에 사유 툴팁(통신 끊김 · 로봇 오류 등) · **다시 체크해 실행하면 재시도**
- **`완료` 건 재실행** — 확인 팝업 `이미 마킹한 지점입니다. 다시 마킹하시겠습니까?` · `[확인]` 시 재실행 · 실행 일시 갱신
  - ⚠ 페인트가 겹쳐 두꺼워지면 재검사를 방해할 수 있음(업무_프로세스 §2-1-2 · §4-1-1) — 팝업 문구에 반영 여부는 하드웨어 확인 후
- 진행 중 `[마킹 실행]` 비활성 · 진행 중 건이 있으면 좌측 레일 `[+]` 검사 불러오기 · `[🗑]` 검사 삭제 차단 + 사유 `마킹이 진행 중입니다.`
- 진행 중 다른 문서 탭으로 이동 — **실행은 계속** · 돌아오면 최신 상태 표시

## 5. 저장 · 기존 데이터 영향

| 항목 | 처리 |
|---|---|
| 저장 시점 | 추가·메모 수정·삭제·상태 변경 **즉시 저장** — 사이드바 `[저장]`(Gain·Gate 수정본)과 **무관** |
| 사이드바 `[↻]` 초기화 | 마킹 목록 **영향 없음** |
| Gain·Gate 사후 조정 | 마킹 영역·동결값 **영향 없음** · 오버레이 위치 유지 |
| 수정 정보 모달 | 마킹 변경은 **수정 이력에 넣지 않음**(교정 설정값 수정과 다른 성격) |
| raw · 교정 설정값 2세트 | 변경 없음 · 마킹 목록은 검사에 귀속된 **별도 레코드** |
| 좌측 레일 `[🗑]` 검사 삭제 | 마킹 목록도 함께 삭제 — `완료` 마킹이 있으면 삭제 모달 본문에 `마킹 완료 N건의 기록도 함께 삭제됩니다.` 추가 |

- 저장 구조 상세는 확정 후 `03_dev_handoff/Result_Analysis_Storage_Spec`에 `markings[]`로 추가

## 7. 재확인 결과 — 보관하지 않음

- 검사자가 마킹 지점을 **수동 장비로 재확인**(10/28 회의) · 결과는 현장 기록지·웹에 기록
- ERUT는 마킹 목록(번호·좌표·동결값·실행 상태)만 보관 · **재확인 결과 입력 UI 없음**
- 이유 — 재확인 결과는 결함 분류·합격 판정(업무_프로세스 §4-1-1)으로 이어져 웹 책임

## 8. 개발·고객 확인 질문 (Notion `🛠️ 개발팀 논의 필요/수정 사항`에 확정 후 등록)

1. **두산** — 시방서의 "합격 기준 초과 시 마킹"이 **기록 기준 초과(검출)**를 뜻하는가
2. **개발·하드웨어** — 로봇을 다시 붙였을 때 **이 검사의 시작점**인지 판별하는 방법 · 마킹 위치 허용 오차 · 장거리 주행 시 엔코더 누적 오차
3. **하드웨어** — 마커와 탐촉자 사이 거리(오프셋) 보정 · 영역(시작/끝)과 번호를 물리적으로 표시할 수 있는가(점·선·번호)
4. **좌표 환산** — 경사각 채널은 반사체의 표면 위치가 탐촉자 위치와 다름. 굴절각·음로로 환산한 위치를 보낼지, 탐촉자 위치를 보낼지
5. **통신** — Sight → 로봇 마킹 요청 경로(Bridge PC 경유 여부) · 진행·완료·실패 상태 회신 방식 · 로봇 연결 상태를 Sight가 알 수 있는가
