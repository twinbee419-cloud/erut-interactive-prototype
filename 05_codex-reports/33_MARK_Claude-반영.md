## 2. 마킹 구조 전환 — 사용자 확정

**결과 분석은 마킹 목록을 만들고 관리만 한다. 실행과 실행 결과는 자동화 장비 제어 페이지(아직 기획 전)가 맡는다.**

| 항목 | 이전 (29~32번) | 지금 |
|---|---|---|
| 실행 | 결과 분석에서 체크 → `[마킹 실행]` | **자동화 장비 제어 페이지** — 결과 분석에서 `[저장]`하면 그 페이지 목록에 반영 |
| 상태 | 결과 분석이 로봇 회신으로 갱신 | **자동화 장비 제어 페이지가 보내는 값을 표시만** (`대기`·`진행중`·`완료`·`실패`) · 즉시 반영 |
| 저장 | 추가·삭제·상태 변경 즉시 저장 | **헤더 공통 `[저장]`** — 교정 탭 변경과 한 번에 · 마킹만 바뀌면 수정 정보 모달 없음 · ⓘ 수정 정보·수정 일시 변경 없음 |
| 메모 | 선택 · "관찰 사실" | **마킹 사유 · 필수** · 100자 · `대기`에서만 수정 · 이후 readonly |
| 삭제 | 대기·실패(오류) | **`대기`만** · 클릭 즉시 목록에서 빠짐 · `[저장]` 시 확정 |
| 목록 UI | 표 → 2~3줄 목록 | **카드** — 1줄 번호+상태 / 2줄 채널·X·Y·`Depth`·`FSH` / 마킹 사유 · `대기` = 항상 펼침+🗑 · 그 외 = 아코디언 |
| 필터 | — | `진행 상태` 드롭다운 · 다중 선택 4종 · `[↺]`·`[✓]` · 기본 `전체` |
| 빈 상태 | — | `결함이 의심되는 부분에 드래그하여 마킹해 보세요.` |
| 실패 사유 툴팁 | — | 문구 5종 · **`[검토 필요]`** (로봇 회신 형식 확정 후) |
| 동시 변경 | — | `[저장]` 전에 그 건이 자동화 페이지에서 시작됐으면 그 건의 삭제·수정만 취소 · 팝업 `마킹이 이미 시작된 항목은 삭제·수정할 수 없습니다.` + 번호 |
| 저장 안 한 변경 | — | 문서 탭 왕복 = 유지(팝업 없음) · 결과 분석 탭 `[×]` 닫기·다른 검사 불러오기 = `공통 팝업 - 닫기` (현행 개발 동작과 같음) |
| 검사 삭제 | 진행 중 차단 | `진행중` 마킹이 있으면 삭제 불가 · 그 외 마킹도 함께 삭제(자동화 목록에서도 제거) |
| 사이드바 헤더 | `◈ 교정` | **`◈ 결과 분석`** + 교정 탭 `[↻]`·`[저장]` / 마킹 탭 `[저장]` |

## 4. Codex 검토 요청

1. **3문서 분할 후 참조** — 세 문서 사이 참조(공통 저장 · 사후 변경 허용 범위 · 마킹 탭 · 검사 불러오기 팝업)와 다른 Notion 문서의 `[C-PRJ-06] 결과 분석` 참조가 끊기거나 다른 문서를 가리키는 곳.
2. **공통 `[저장]` 규칙 일관성** — 교정만 / 마킹만 / 둘 다 바뀐 경우의 모달·수정 정보·`수정 일시` 처리가 사이드바(교정) · 사이드바(마킹) · 저장 사양 §3-1·§4에서 같은지 · `[↻]`·저장 안 한 변경·검사 삭제와 충돌하는지.
3. **마킹 탭에 실행 쪽 규칙 잔여** — 체크박스·`[마킹 실행]`·`결과 미확인`·`[표시 확인됨]`·재시작 복구·즉시 저장 같은 이전 규칙이 Notion 3문서·저장 사양·인수인계서에 남은 곳.
4. **구현 공백** — 결과 분석과 자동화 장비 제어 페이지가 같은 `markings[]`를 쓸 때 화면이 알아야 할 조건(상태 즉시 반영 · 동시 변경 판정 시점 · 저장 전 화면 상태의 `대기` 표시)이 비어 있는지. 실행 쪽 규칙은 §5로 제외.
