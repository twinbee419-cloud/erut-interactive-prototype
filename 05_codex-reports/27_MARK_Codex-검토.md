# 의심 지점 마킹 초안 구현 가능성 검토

> Codex · 2026-11-06 · 대상: `26_MARK_Claude-기획초안.md` §1~§7. Notion `[C-PRJ-06] 결과 분석`·`[C-PRJ-03] 종합 결과`·`[C-RPT-02] 스캔 보고서`를 새로 읽고 대조함. 초안 §8 및 기존 미결은 제외. 아래는 발견과 질문이며 기획 판정이 아님.

**blocking 1 · should-fix 6 · nit 0**

## 발견

### B1 · blocking · 자동 후보가 여러 채널에 걸칠 때 필수 `채널`을 정할 수 없음

1. **무엇이:** 자동 후보 경로의 마킹 `채널`은 ‘그 구역을 검출한 채널’ 1개인데, C-scan은 여러 채널을 겹쳐 표시함. 두 채널 이상이 같은 구역을 검출한 경우와, 펼친 채널이 후보를 검출한 채널과 다른 경우의 선택 규칙이 없음. 데이터 없음 예외는 ‘선택 채널’을 기준으로 적혀 있어 후보 경로에도 어느 채널을 검사하는지 갈림.
2. **어디서:** `26_MARK_Claude-기획초안.md:49,61,74`; Notion `[C-PRJ-06] 결과 분석` §좌측 스캔 영역·§우측 상단 A-scan.
3. **왜 문제인가:** 저장 필수 항목인 채널과 그 채널의 깊이·에코 높이를 후보 1건에 일관되게 배정할 수 없음.
4. **확인 질문:** 자동 후보를 채널별 개별 사각형으로 생성하는가? 겹친 후보 1개를 선택하면 채널을 어떻게 정하고, 데이터 없음 검사는 펼친 채널과 후보 채널 중 어느 쪽에 적용하는가?

### S1 · should-fix · 저장 전 Gain·Gate로 만든 마킹의 값이 설정 저장 없이 남을 수 있음

1. **무엇이:** Gain·Gate 변경은 C-scan에 즉시 반영되지만 `[저장]` 전에는 폐기 가능함. 마킹은 추가 즉시 저장하고 깊이·에코 높이를 추가 시점 값으로 동결함. 미저장 설정으로 마킹한 뒤 설정 변경을 폐기하는 조합의 기준이 없음.
2. **어디서:** `26_MARK_Claude-기획초안.md:62-68,117-121`; Notion `[C-PRJ-06] 결과 분석` §검사 불러오기·§우측 상단 A-scan·§저장·초기화·삭제; `03_dev_handoff/Result_Analysis_Storage_Spec_v1.0.md:96-99`.
3. **왜 문제인가:** 남은 마킹의 동결값이 보관 중인 `origin`·`current` 어느 설정에서도 재현되지 않을 수 있음. 저장 순서에 따라 같은 영역의 기록값이 달라짐.
4. **확인 질문:** 마킹 추가 시 미저장 Gain·Gate를 기준으로 삼아도 되는가? 허용한다면 그 시점 설정을 마킹에 함께 보관하는가, 아니면 마지막 저장된 `current`로 계산하는가?

### S2 · should-fix · 영역의 ‘최대 진폭 지점’ 산출 기준이 비어 있음

1. **무엇이:** 깊이와 에코 높이를 영역 안 최대 진폭 지점에서 채우지만, 선택 게이트 안의 피크인지 전체 A-scan 피크인지, 동률·복수 에코일 때 어떤 지점을 고르는지 정하지 않음.
2. **어디서:** `26_MARK_Claude-기획초안.md:60-68`; Notion `[C-PRJ-06] 결과 분석` §우측 상단 A-scan·§우측 사이드바 — 채널별 조정.
3. **왜 문제인가:** 같은 사각형과 채널에서도 구현에 따라 서로 다른 깊이·%FSH가 저장될 수 있음.
4. **확인 질문:** 영역 내 최대값은 해당 채널의 현재 선택 게이트가 포착한 피크를 비교하는가? 복수 피크·동률이면 어떤 값을 저장하는가?

### S3 · should-fix · 3D에서 목록 행을 누를 때 이동 대상이 없음

1. **무엇이:** 3D View에서도 목록 사용을 허용하지만, 행 클릭 동작은 ‘C-scan으로 이동·하이라이트’로만 정의됨. 3D View ON에서는 좌측 C-scan이 3D 모델로 전환됨.
2. **어디서:** `26_MARK_Claude-기획초안.md:36-38,83`; Notion `[C-PRJ-06] 결과 분석` §3D View.
3. **왜 문제인가:** 동일한 행 클릭에 2D·3D별 화면 반응을 구현할 수 없음.
4. **확인 질문:** 3D에서 행을 누르면 2D로 전환해 해당 영역으로 이동하는가, 3D 모델에서 위치를 강조하는가?

### S4 · should-fix · 일괄 실행의 부분 실패·이탈·재실행 범위가 불명확함

1. **무엇이:** 선택 건을 번호순 실행하고 각 행이 완료·실패로 바뀌지만, 중간 한 건 실패 시 남은 행의 실행 여부가 없음. 문서 탭 이동은 계속 실행한다고 적었으나 프로그램 종료·재시작 시 진행중 행의 처리도 없음. `대기`·`실패`·`완료`를 함께 체크하면 완료 건 재실행 확인의 적용 범위도 정해져 있지 않음.
2. **어디서:** `26_MARK_Claude-기획초안.md:81-86,102-109,117`.
3. **왜 문제인가:** 동일한 실행 요청 후 일부 행이 `대기`·`진행중`·`실패` 중 어디에 남는지, 재실행 시 어느 행이 전송되는지 구현마다 달라짐. §8의 통신 경로·회신 방식 질문과는 별개의 **화면 상태 전이** 문제임.
4. **확인 질문:** 한 행이 실패하면 다음 행을 계속 실행하는가? 종료·재시작 후 미완료 행은 어떻게 표시·재시도하는가? 완료 건을 섞어 체크한 요청의 확인을 취소하면 나머지 행도 실행하지 않는가?

### S5 · should-fix · ‘즉시 저장’ 실패 시 물리 실행과 기록의 순서가 없음

1. **무엇이:** 추가·삭제·상태 변경을 즉시 저장한다고만 하며 저장 실패 시 표시·재시도·마킹 실행 가능 여부가 없음.
2. **어디서:** `26_MARK_Claude-기획초안.md:59,85,104,113-124`.
3. **왜 문제인가:** 번호가 확정·보존되지 않은 마킹을 로봇에 보내면 실제 표시와 검사 기록이 갈라질 수 있음. 번호를 현장 기록지·웹이 참조한다는 확정 사항과도 연결됨(`26_MARK_Claude-기획초안.md:24,59`).
4. **확인 질문:** 추가 저장 실패 시 행과 번호는 어떻게 처리하는가? 실행 전 해당 마킹과 `진행중` 상태의 저장 성공을 필수로 확인하는가?

### S6 · should-fix · 공유한 사각형의 캡처·마킹 경계가 비어 있음

1. **무엇이:** 직접 마킹은 기존 영역 선택(▣) 사각형을 사용함. 그 사각형은 캡처의 측정 오버레이이기도 하고, 캡처 이미지는 측정 오버레이를 포함함. 마킹 추가 후 번호·상태 오버레이까지 캡처되는지와 원래 측정 사각형을 수정·삭제할 때 마킹 좌표가 독립적으로 남는지가 적혀 있지 않음.
2. **어디서:** `26_MARK_Claude-기획초안.md:19,38,48-53,60,83-85`; Notion `[C-PRJ-06] 결과 분석` §좌측 스캔 영역; `[C-RPT-02] 스캔 보고서` §캡처 생성·§캡처 시점 설정값 동결; `[C-PRJ-03] 종합 결과` §측정·캡처.
3. **왜 문제인가:** 캡처와 마킹은 별도 기록이라는 확정 사항에도 같은 선택 영역·화면 오버레이를 사용해, 캡처 이미지와 마킹 목록이 서로의 변경에 영향을 받는지 구현 기준이 갈림.
4. **확인 질문:** 캡처 이미지에 마킹 번호·상태 오버레이를 포함하는가? 마킹 추가 시 사각형 좌표는 측정 객체에서 복사되어 이후 수정·삭제와 독립하는가?

## 확인된 경계

- 초안의 마킹 진입은 완료 검사 결과 분석에 한정되고 `[C-PRJ-03]`에 신규 마킹 동작을 요구하지 않음(`26_MARK_Claude-기획초안.md:18,34-38`; Notion `[C-PRJ-06]` §진입). 기존 `[↻]`·수정 정보·검사 삭제와 마킹 기록의 관계도 §5에 구분됨. 다만 S1·S5의 저장 예외는 남음.
- 마킹 항목에 유형·등급·합격 여부는 없고 재확인 결과 입력도 없음(`26_MARK_Claude-기획초안.md:27-30,55-68,135-139`; `ERUT_인수인계서_Codex.md` §2 ‘검출 vs 판정’). 초안 §6의 보고서 기재 항목은 명시적으로 후속 설계로 남겨 이번 결함 건수에 넣지 않음.
