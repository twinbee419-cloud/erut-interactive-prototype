## 남은 대조 결과

1. **should-fix — S4 게이트 선택 경로가 한쪽 방향만 정의됨.** 파형 영역 §하단 인라인 바—Gain은 활성 게이트 2개 이상일 때 **파형에서 클릭한 게이트**를 `[✨]` 대상으로 삼음. 사이드바 §④ 기준 에코 기록 행은 **측정 게이트**를 `[↑ Record]`의 기록 게이트로 저장하고, 측정 게이트 변경 시 파형 선택 게이트를 바꾼다고만 함. 새 성공 상태 해제 조건도 *측정 게이트 변경*과 *선택 게이트 Start·Width 변경*만 명시함. 따라서 측정 게이트 A를 둔 채 파형에서 B를 클릭했을 때, `[✨]` 대상과 Record 저장 게이트가 달라질 수 있음. **확인 질문:** DGS 설정 중 파형 클릭을 측정 게이트에 역연동하는가, 아니면 Record를 비활성·차단하는가? 두 Notion 문서의 양방향 선택·성공 상태 조건에 반영 필요.
2. **should-fix — 저장 예시의 TCG/DGS 동시 기재가 택일 규칙과 다름.** 저장 사양 §3 JSON `:60-61`은 한 채널에 `tcgPoints`와 `dgs`를 함께 채웠지만, 바로 아래 `:67`은 둘 중 하나만 채운다고 함. 구현자가 예시를 그대로 따르면 혼재 금지 규칙과 충돌함. **확인 질문:** 예시를 TCG·DGS 별도 채널로 나누거나 한쪽 값을 비워 택일을 보여 줄 것인가? 수정 대상은 저장 사양 §3 예시.
3. **should-fix — S6 예외가 일반 규칙 본문에는 반영되지 않음.** 사이드바 §④는 영점·음속 미완료 시 *DGS 블록 전체 비활성*이라고 명시하고 이를 예외라고 부름. 그러나 같은 문서 §섹션 간 의존 관계의 제목은 여전히 *순서 강제 없음*, 본문은 선행 미완료 시 *경고 배너·저장 허용·유효 판정 보류*라고 예외 없이 적음. §④를 먼저 읽으면 뜻은 알 수 있지만, 일반 규칙만 읽으면 DGS 동작을 다르게 구현할 수 있음. **확인 질문:** §섹션 간 의존 관계의 제목과 선행 미완료 규칙에 DGS 예외를 직접 표기할 것인가? 어느 서술을 택할지는 여기서 판정하지 않음.
4. **nit — 새 문구 오타.** 사이드바 §④ `[↑ Record]`의 성공 상태 해제 조건에 `바뀜면`으로 적힘. **확인 질문:** 해당 문구를 정정할 것인가?
